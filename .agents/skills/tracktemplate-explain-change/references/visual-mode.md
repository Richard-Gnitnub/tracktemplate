# Visual explanation mode

Use a visual only when the user requests one or a dynamic relationship is
materially clearer through interaction: state transitions, ordering,
Undo/Redo, migration, cache invalidation, geometry transformations, export
staging or concurrent/event flow.

## Boundary

Create at most one self-contained HTML file in a newly allocated operating-
system temporary directory. Keep it out of the repository and do not deploy or
persist it. The chat explanation remains the primary handoff.

- Use sanitised fictional records; never embed operator documents, credentials,
  private paths, third-party evidence or production payloads.
- Use only inline HTML, CSS and JavaScript. Make no network calls and load no
  external assets, packages, analytics or storage.
- Do not import or execute repository modules, FreeCAD, macros or production
  code. Model only the named concept and label every simplification.
- Do not represent the visual as runtime, GUI, geometry, persistence or export
  evidence.

## Interaction

Show:

1. the initial state and relevant identities;
2. the available operator or system action;
3. the resulting state or transition; and
4. the invariant, ordering or rollback rule being illustrated.

Prefer one purposeful step, scrub, reorder or input control that reveals cause
and effect. Avoid decorative animation. Provide keyboard access, visible focus,
adequate contrast, text alternatives and reduced-motion behaviour.

## Verification

Open the temporary file only when the available environment and user authority
permit it. Exercise every control, inspect initial and boundary states, and
confirm that the page works without network access. If browser execution is
unavailable, report that limitation rather than claiming the visual ran.

Report the exact temporary path, the concept modelled, sanitisation performed,
controls checked and every material difference from production behaviour.
