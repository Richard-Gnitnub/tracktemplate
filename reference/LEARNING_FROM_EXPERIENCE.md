# Learning from Experience

Status: **append-only historical process ledger established on 2026-07-22.**

## Ledger rules

This document records durable adaptations learned from actual project work so
later development cycles do not repeat avoidable mistakes. It owns no live
phase status, requirement, risk state or acceptance decision. Those remain in
[PROJECT_PLAN.md](PROJECT_PLAN.md) and the applicable policy, contract or
open-phase evidence record.

Add a row only when an observation has evidence and led to a reusable process,
architecture or validation change. Link to the owning payload instead of
copying its technical detail. Do not edit an old row to make it match later
knowledge; append a correction or successor lesson.

For each new lesson, ask which canonical owner and workflow must change,
whether deterministic enforcement is proportionate, and which regression or
semantic mutation prevents recurrence. If an executable control would add more
complexity than the risk that it controls, record that reason in the owning
change evidence. The ledger records the lesson. It does not own the adaptation.

| LFE-019 / STE retrieval assurance 2026-08-24 | Agents used a large authorised source again and again during usual documentation work. Each complete-source inspection used too much read time and agent context and gave source material that the task did not use. Targeted retrieval does not stop an agent who uses a lookup result as the complete applicable requirement set. Low source efficiency, not the authorised source or requirement set, caused the problem. The retrieval architecture keeps source authority, full applicability, targeted retrieval, deterministic pre-checks, and independent review in different authority boundaries to increase source efficiency. It preserves full applicability for Issue 9, while drift controls stop the use of only some writing rules and conformance claims without evidence. | TrackTemplate binds the source-derived index and derived cache to the [source identity](external/asd-ste100/README.md#source-identity-and-copyright-boundary), and the index maps rule families but does not replace the authorised source. Targeted retrieval controls source text for this task. The technical-term register owns technical nouns and technical verbs, and concise lookup output and deterministic pre-checks decrease agent context that is not necessary. Documentation skill routing connects each review to its canonical owner, and review receipts, drift controls, and independent review stop partial conformance claims. The [agent workflow](AGENT_WORKFLOWS.md#tt-doc-001-workflow-integration) lets an agent use complete-source inspection only for bounded conditions. The [Technical Documentation Profile](ENGINEERING_POLICY.md#tt-doc-001-tracktemplate-technical-documentation-profile) owns canonical policy, the [validation owner](VALIDATION.md#asd-ste100-retrieval-assurance) owns validation, the [agent workflow](AGENT_WORKFLOWS.md#tt-doc-001-workflow-integration) owns routing, and the [STE lookup](external/asd-ste100/README.md#local-retrieval-interface) owns local operation. | When agents must read a large authorised source again and again, optimise the access path, not the requirement set. Bind the derived cache and retrieval index to the official source identity. Keep full applicability and targeted retrieval in different authority boundaries. Give only the source material that is necessary for the task. Use workflow, validation, and independent review controls. Thus, an agent cannot use partial retrieval as evidence of partial conformance. |

## Using the ledger

At the start of a materially similar tranche, review only the relevant rows
and follow their linked current controls. At phase close or a later formal QA
audit, append newly evidenced lessons; do not use this ledger as a checklist
substitute or a progress report.
