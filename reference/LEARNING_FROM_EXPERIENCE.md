# Learning from Experience

Status: **append-only historical process ledger established on 2026-07-22.**

## Ledger rules

This document records process changes from project experience. These changes
help later development cycles prevent the same mistakes. It owns no live
phase status, requirement, risk state or acceptance decision. Those stay in
[PROJECT_PLAN.md](PROJECT_PLAN.md) and the applicable policy, contract or
open-phase evidence record.

If an observation has evidence and caused a repeatable process, architecture,
or validation change, add a row. Link to its canonical record. Do not copy the
technical detail. Do not edit an old row to make it agree with later knowledge.
Add a correction or successor lesson.

For a new LFE record, use this procedure:

1. Find the canonical owner.
2. Find the applicable workflow.
3. If a semantic control can prevent the same problem, add the semantic control.
4. If a regression test is necessary, add the regression test.
5. If a semantic mutation is necessary, add the semantic mutation.
6. If no semantic control is necessary, record the cause in the canonical owner.

The LFE record contains the applicable finding. The LFE record does not become
a canonical owner, workflow, or semantic control.

| LFE-017 / Phase 6 exporter fault-model decision 2026-08-15 | Independent reviews initially found material descriptor, advisory-lock, recoverability and diagnostic defects, producing valuable systemic repairs. Repair violations of retained safety invariants, but do not turn every arbitrary instruction-level interruption probe into a release blocker. | LFE-018 / TT-DOC-001 documentation architecture 2026-08-15 | TrackTemplate had many governance and evidence controls. Machines could validate many controls. Long text had many subjects. | LFE-019 / STE retrieval assurance 2026-08-24 | Agents used a large authorised source again and again during usual documentation work. Each complete-source inspection used too much read time and agent context and gave source material that the task did not use. Targeted retrieval does not stop an agent who uses a lookup result as the complete applicable requirement set. Low source efficiency, not the authorised source or requirement set, caused the problem. The retrieval architecture keeps source authority, full applicability, targeted retrieval, deterministic pre-checks, and independent review in different authority boundaries to increase source efficiency. It preserves full applicability for Issue 9, while drift controls stop the use of only some writing rules and conformance claims without evidence. | TrackTemplate binds the source-derived index and derived cache to the [source identity](external/asd-ste100/README.md#source-identity-and-copyright-boundary), and the index maps rule families but does not replace the authorised source. Targeted retrieval controls source text for this task. The technical-term register owns technical nouns and technical verbs, and concise lookup output and deterministic pre-checks decrease agent context that is not necessary. Documentation skill routing connects each review to its canonical owner, and review receipts, drift controls, and independent review stop partial conformance claims. The [agent workflow](AGENT_WORKFLOWS.md#tt-doc-001-workflow-integration) lets an agent use complete-source inspection only for bounded conditions. The [Technical Documentation Profile](ENGINEERING_POLICY.md#tt-doc-001-tracktemplate-technical-documentation-profile) owns canonical policy, the [validation owner](VALIDATION.md#asd-ste100-retrieval-assurance) owns validation, the [agent workflow](AGENT_WORKFLOWS.md#tt-doc-001-workflow-integration) owns routing, and the [STE lookup](external/asd-ste100/README.md#local-retrieval-interface) owns local operation. | When agents must read a large authorised source again and again, optimise the access path, not the requirement set. Bind the derived cache and retrieval index to the official source identity. Keep full applicability and targeted retrieval in different authority boundaries. Give only the source material that is necessary for the task. Use workflow, validation, and independent review controls. Thus, an agent cannot use partial retrieval as evidence of partial conformance. |
| LFE-020 / visible recovery state 2026-08-24 | The stash stayed after `main` contained its work because branch and worktree commands did not show its recovery label. The recovery audit found all work in named Git state, but did not complete stash reconciliation or disposition. Independent review rejected the recovery result because the stash stayed in the stash inventory. The [recovery evidence](current/PHASE_EVIDENCE.md#visible-recovery-state-workflow-migration) records B/I/W/U reconciliation and shows that no unique content stayed only in the stash. During independent review, a command made an emergency stash by accident. It stayed in unresolved recovery state until commit `1ca5b2d` contained its work and the owner authorised disposition. | TrackTemplate uses feature branches, recovery branches, recovery worktrees, and explicit commits as named Git state for planned preservation and handoff. Local evidence uses a checksum manifest and independent preservation. TrackTemplate uses an emergency stash only as temporary recovery state. The [recovery policy](RECOVERY_AND_BACKUP.md#visible-recovery-state) makes stash inventory, stash ownership, recovery purpose, unique content, and stash disposition necessary. The procedure fails closed when it cannot complete stash reconciliation or when the stash inventory contains a stash. The [workflow](AGENT_WORKFLOWS.md#session-continuity) routes each agent to the canonical owner. | Use visible recovery state with feature branches, recovery branches, recovery worktrees, and explicit commits for planned preservation or handoff. Use an emergency stash only as temporary recovery state. While the stash inventory contains a retained stash, do not give the recovery gate a complete result. If a retained stash has no stash ownership, do not give the recovery gate a complete result. If its recovery purpose or stash disposition is missing, do not give the recovery gate a complete result. Reconcile each stash. Preserve unique content in named Git state or independent preservation. Before a stash disposition, validate that unique content stays available. Then, get applicable authority. |

## Using the ledger

At the start of similar work, review only the applicable rows. Obey their
linked current controls. At phase close or a later formal QA audit, add new
lessons with evidence. Do not use this ledger as a replacement for a checklist
or a progress report.
